# Module contracts

API base `/api`. JSON success is the value itself (collections normally `{items,total,page,pageSize}`). Error `{error:string, details?:unknown}`. Cookie session; `GET /api/auth/session` returns `{user:{id,name,email,role,permissions}|null, csrfToken:string}`. POST login `{email,password}` returns same authenticated shape. POST logout. Fetch credentials same-origin; send `x-csrf-token` on all non-GET dashboard calls. Public tracking/unsubscribe and Bearer scheduler routes exempt from CSRF.

`APP_URL` remains the actual dashboard and generated-link URL. `ALLOWED_ORIGINS` configures API-only CORS: blank permits the `APP_URL` origin; comma-separated exact canonical HTTP(S) origins add trusted origins; `*` permits any valid HTTP(S) API origin. Responses omit `Access-Control-Allow-Credentials`. Cookie sessions remain same-origin, with CSRF and server permissions enforced; wildcard CORS does not enable a separately hosted authenticated frontend. Environment changes require an application restart.

Database Knex instance exported `db` from `server/db.ts`. IDs UUID strings length 36; UTC `datetime(3)` JS Date values; JSON fields stored JSON and decoded with `json(value,fallback)` exported there. DB uses snake_case; API uses snake_case for domain fields. `id()` from `server/lib/util.ts`. `HttpError(status,message)` there. `audit(actorId,action,entityType,entityId,details,trx?)`. `requireUser` and `permit(permission)` in `server/auth.ts`; owner has all permissions, team members use permission array. `req.user` populated middleware. settings permission `settings:write`, contacts `contacts:write`, campaigns `campaigns:write`, inbox `inbox:write`, health `system:write`. All authenticated users read.

Shared `business_settings`: singleton id='agency', `data` JSON. `getSettings(trx?)` from server/settings.ts returns merged defaults; `defaultSettings` exported. Includes agency_name,website,logo_url,sender_name,business_address,signature,timezone,application_cap(20),provider_cap(100),sending_days([1,2,3,4,5]),sending_start('09:00'),sending_end('17:00'),min_interval_seconds(180),followup_delays([3,7]),max_retries(3),poll_interval_seconds(60),sync_stale_seconds(900),paused(true),open_tracking(false),click_tracking(false),retention_days(90),filter_bots(true),categories,tags,custom_fields,unsubscribe_copy. Timezone America/Los_Angeles.

`email_accounts`: id,label,email,sender_name, smtp_host, smtp_port,smtp_security('tls'|'starttls'),smtp_username,smtp_secret,imap_host,imap_port,imap_security('tls'),imap_username,imap_secret,status('inactive'|'active'|'paused'|'error'),provider_policy('opt_in_only'),is_default,verified_at,last_sync_at,last_error,created_at,updated_at. secrets encrypted via `encryptSecret`/`decryptSecret` from server/lib/crypto.ts. `safeAccount` strips secret fields. `validateMailTarget(host,port,kind)` from server/lib/mail-target.ts async returns public pinned IP. Inbox engine `GET /api/inbox?classification=&account_id=` `{items}` conversation list, grouped by Message-ID/In-Reply-To/References within the same mailbox and normalized external participant. Grouping uses header metadata before filtering and the 200-conversation limit; only the latest body preview is loaded for each row. Each summary uses the root database ID as `id`/`thread_id`, root subject, latest metadata/delivery status, `latest_subject`, `latest_message_id`, `message_ids`, and `message_count`. New compose without reply headers stays separate even for an identical recipient/subject; subject similarity never joins conversations. Known foreign/ambiguous participant references are ignored. GET `/:id` accepts any member message ID and returns its original fields plus the chronological header-linked `thread`, `thread_id`, `conversation_subject`, `message_count`, `reply_message_id` (latest member ID), and optional matching-address contact; PATCH `/:id` `{contact_id?,assigned_to?}` (legacy manual matching must invoke stop behavior); POST `/compose` `{account_id,to,subject,body_text}` and POST `/:id/reply` `{body_text}` require `inbox:write` and queue one-to-one mail through the shared capacity path, returning 202 `{job_id}`. Neither requires or creates a contact; replies derive the recipient from the original message, ignoring incorrect legacy contact matches. Compose validates a single email address (254 max), subject (1–998, no CR/LF), and text body (1–100000). POST `/api/accounts/:id/sync` owner/system:write queues/request sync only (no sending). `GET /api/overview` `{metrics:{accepted,unique_opens,unique_clicks,human_replies,bounces,unsubscribes,qualified,won,active_campaigns},capacity:{used,cap,provider_cap},health:{last_heartbeat,last_sync,pending_jobs,failed_jobs},activity:[]}`. `GET /api/analytics?from=&to=&campaign_id=&account_id=` same metrics plus series,denominators; `GET /api/analytics/export.csv`. `GET /api/health` DB queue/mailbox/scheduler health. POST `/api/health/retry` retries safe failed jobs only; ambiguous sends remain held. POST `/api/health/reconcile` `{attempt_id,resolution:'accepted'|'not_sent'}` owner only with audit; accepted schedules following step, not_sent allows manual retry. Public GET `/healthz` liveness.

Engine exports `campaignRouter`, `templateRouter`, `inboxRouter`, `runWorker({budgetMs?,maxJobs?,syncOnly?,inboxOnly?})`, `suppressEmail(email,reason,source,actorId?,trx?)`, and `publicRouter` for tracking/unsubscribe. Native Next.js Node Route Handlers delegate Web Requests to `handleRequest` in `server/app.ts`. Domain routers use `server/http.ts`, with no Express runtime. The Node `createApp()` adapter exists for integration fixtures only. Dashboard pages use App Router paths and a shared authenticated client layout. Scheduler `POST /internal/tick` is authenticated by timing-safe Bearer env SCHEDULER_SECRET, server max budget <= 20s. All sending defaults paused and env LIVE_SEND_ENABLED=false; no test suite may send mail.

Request bodies are streamed with byte limits: API JSON 2200 KiB, scheduler JSON 1 KiB, public unsubscribe forms 2 KiB. Malformed/scalar JSON and unsupported compression are rejected before domain mutations; duplicate form/query fields retain multiple values and prototype-like names remain ordinary input. Set-Cookie values remain distinct in native Web Responses. API responses are uncached, with session/CSRF/permission checks preserved. HTML uses a per-request CSP script nonce. Knex pools are reused across Next reloads while tests retain isolated pool ownership. `TRUST_PROXY_HOPS` must match the verified host topology; without a trusted forwarded address Next's API uses an aggregate `unknown` IP rate-limit bucket.

## Implemented refinements

- Database compatibility targets MySQL 8+ or MariaDB 10.11+ using the same Knex/mysql2 layer. All business tables explicitly use InnoDB. Local execution was verified on MariaDB 11.4.8; the actual Hostinger engine remains a verification gate.
- Mailbox password write fields are `smtp_password` and `imap_password`; responses expose only presence flags. A connection edit invalidates prior validation, and concurrent validation cannot approve a stale configuration.
- `send_attempts` keeps the stable logical message/attempt and a monotonic `submission_count`. `send_attempt_events` stores immutable per-submission outcomes, so a temporary rejection remains reportable after a later accepted retry.
- `messages` records per-message `open_tracking`/`click_tracking`, plus `reviewed_at`/`review_action`. `POST /api/inbox/:id/review` accepts `{action:'resume'|'stop'}`. Individual review decisions persist while another hold remains; human stops and suppression cannot be cleared through review.
- New manually written compose/reply jobs use `is_manual:true` and immutable normalized `manual_recipient`. Optional `contact_id` is logging metadata and never decides the SMTP recipient. `manualRecipientEligibility` checks that exact address for suppression and revoked consent at enqueue, reservation, and pre-submission; manual mail does not require campaign opt-in, create contacts, or upgrade consent. It retains live-send/global pause, active validated mailbox, fresh sync, rolling capacity, and unknown-outcome gates. Individually written manual mail skips campaign business-hour windows and campaign spacing. Campaign/test timing is unchanged. Plain manual messages add no marketing footer/tracking and require no business address. Campaign/test consent and marketing rules are unchanged.
- Replies additionally include `reply_source_id` (original database message ID), normalized `reply_recipient` (`from_email` for inbound, `to_email` for outbound), and original threading headers. Reservation and pre-submission verify those anchors and any existing attempt/message recipient. New manual replies ignore legacy contact matches; older non-manual queued replies retain strict contact/source checks. Unanchored or drifting legacy replies are canceled for review, never silently retargeted. The legacy inbound matching API still rejects a contact whose email differs from the sender. Incoming reference matching accepts contactless messages only when references identify one external recipient in the same mailbox, and verifies the incoming sender before classifying a human reply.
- `email_accounts.last_sync_at` is the freshness gate and is invalidated during scanning/failure. `last_successful_sync_at` preserves the last complete catch-up time for health displays. UID SEARCH bounds actual messages rather than sparse numeric UID spans.
- Analytics denominators are `smtp_accepted_messages`, `open_tracking_messages`, `click_tracking_messages`, and `unique_recipients`; raw events and filtered unique counts remain separate. Qualified/won values are explicitly current agency stage snapshots.
- Reconciliation accepts optional `accepted_at` as an offset ISO timestamp supported by provider evidence. It must fall between reservation and now. Without an exact verified timestamp, confirmation time is the conservative follow-up baseline. A confirmed `not_sent` resolution explicitly queues a retry through all sending safeguards.
- Contact-list rows include real deal value/currency/outcome, next task, and latest note for the pipeline. Stage changes keep deal outcomes aligned. Sender replacement never changes existing enrollment/account associations.

## Live Inbox execution

Inbox list, outbox and selected thread refresh quietly every 10 seconds while visible; mailbox health refreshes every 30 seconds. Focus/online resumes refresh. Requests do not overlap, stale responses are discarded, and background failures preserve displayed mail and drafts. UI acceptance means SMTP accepted, never confirmed delivery. GET `/api/inbox/outbox?account_id=` returns up to 50 pending/held/failed manual jobs with id, account_id, recipient, subject, status, last_error and timestamps, without content/payload. Outbound messages expose send_status and accepted_at from their actual attempt/job.

POST `/api/inbox/process` accepts strict `{mode?:"inbox"|"sync"}` with session, CSRF and inbox:write; rate limit 20/min/user. It runs bounded work after a user queues compose/reply or requests sync. It never claims campaigns. Durable minute cron remains the browser-independent fallback. `inboxOnly` claims sync and strictly boolean is_manual send jobs; syncOnly takes precedence. Automatic receiving uses a minimum/default 60-second cadence using UTC polling buckets based on scan creation, with pending/leased sync deduplication.

Bearer-only POST `/internal/tick` accepts strict `{action?:"run"|"status"|"install"|"activate-inbox",mode?:"all"|"sync"|"inbox"}`. Existing empty-body callers retain all-job mode. Status returns aggregate job counts, mailbox IDs/state/timestamps and no message data or credentials. Install provisions only the fixed HOSTINGER_ACCOUNT/APP_URL-derived private scheduler directory; requests cannot choose paths or commands. Activation requires the live environment gate, locks settings, refuses leased sends, holds all preexisting queued sends, sets poll interval60/unpauses, audits, and records an idempotency marker. Repeating activation cannot release or hold newer work. It does not process mail. The configured cron uses inbox mode, so campaign work needs its own deliberately enabled scheduler.
